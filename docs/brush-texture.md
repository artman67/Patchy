# Brush Texture

Brush engine context lives in [brushes.md](brushes.md); the binding boundary ("Brush Texture is one static world-anchored grayscale mask") is in [legal-constraints.md](legal-constraints.md).

The texture is one static grayscale value per document pixel: the procedural `textureStyle` grain, or, when `texturePatternId` names a Pattern library tile, that tile's luminance composited over white (`make_brush_texture_tile`), tiled from the document origin at `textureScale` (nearest at 100%, bilinear otherwise). MainWindow resolves the id through `PatternLibrary::resource` and pushes the tile with the dynamics (`CanvasWidget::set_brush_texture_pattern`), again whenever the library changes; a missing or deleted pattern falls back to the grain with no error. Brightness (-150..150) and Contrast (-50..100) adjust the value around mid-gray before Invert. `combine_brush_texture` (core/brush_dynamics) applies the Mode to the tip coverage at Depth; Multiply is the historical formula bit for bit, the other nine follow PhotoCraft's formulas (NOTICE-THIRD-PARTY.md). Patent reasoning: every mode is a fixed function of the static texture value, the tip's own coverage, and the static Depth; the dab's opacity/flow multipliers, where pressure and the other inputs enter, apply only after it, so no stroke input selects, composes, or weights the texture (legal-constraints.md). Height and Linear Height are therefore static too: Depth never follows pressure in Patchy. The Brush Settings Texture page picks the source (grains, then the Pattern library) and shows a missing pattern by its `texturePatternName` ([brush-panels.md](brush-panels.md)). Scripts must pass the Photoshop pattern id; `listVectorResources()` reports a library pattern's storage id as `resourceId`, which does not resolve here. `tool_brush_texture_pattern_tile_drives_coverage`, `brush_texture_modes_combine_static_values` and `ui_brush_texture_pattern_reaches_stroke` pin it.
