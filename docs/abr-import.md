# Photoshop .abr import

`src/psd/abr_reader.*` parses the file; `BrushTipLibrary::import_abr` (src/ui/brush_tip_library.cpp) turns the result into library tips. The brush engine itself is described in [brushes.md](brushes.md); the patent boundaries the mapping respects are in [legal-constraints.md](legal-constraints.md).

## Parsing

`src/psd/abr_reader.*` (`read_abr`): supports v1/v2 and v6 through v10 (subversion 1 = 47-byte, 2 = 301-byte samp entry key whose Pascal uuid names the tip), pairs each `desc` preset with its `samp` bitmap **by uuid** (`sampledData`; several presets may share one tip, and tips no preset names are Dual Brush secondaries that stay out), falling back to file order only when no uuid resolves (order pairing gave myer's first preset the wrong tree), decodes per-row PackBits RLE, downconverts 16-bit, crops to content, caps dimensions at 4096, and skips bad entries with warnings, never failing the file. v6 8BIM tagged blocks are padded to 4-byte boundaries with the padding excluded from the length field; the block walk must skip that padding or the next signature read lands mid-pad (surfaces only when a desc length is not already 4-aligned). PSD and ABR share the descriptor parser and `decode_packbits` in `src/psd/psd_descriptor.*`.

## Computed brushes, folders, and patterns

- **Computed brushes** (`computedBrush`, v1/v2 type 1) import as library tips rendered by `render_computed_brush_mask`: a circle at least 256 px across (Dmtr up to 1024) with a smoothstep falloff over the outer (1 - Hrdn) of the radius. `Angl`/`Rndn` become the static tip shape, so the engine squashes and rotates the circle per dab exactly like a sampled tip. A rendered bitmap keeps the library bitmap-only (sidecar plus PNG) and lets every engine path, cursor, and preview use it unchanged; a procedural library entry would have needed a second tip kind through the picker, panels, and canvas.
- **Size**: `Dmtr` becomes the tip's `defaultSize` sidecar value when the preset captured its size (`useBrushSize`, Photoshop's "Capture Brush Size in Preset"; absent counts as captured, the pre-CC behavior). Picking the tip applies it like Photoshop (`CurrentBrush::pick_tip`, gated with the imported Flow/Airbrush).
- **Folders**: the `phry` block lists `Grup` {name} / `groupEnd` / one `preset` per desc preset in order; each tip lands in "File / Group / Sub" (the library has one folder level). A hierarchy whose preset count differs from the desc list is ignored.
- **Patterns**: a textured preset keeps its `Txtr` `Idnt`/`Nm  ` as `texturePatternId`/`texturePatternName`. The reader returns only the `patt` records some brush references (by id, or by name when the id is absent, which re-points the brush at the embedded id), and `import_abr` decodes them one at a time (`decode_abr_pattern`) into the Pattern library in a folder named after the file, skipping ids the library already has. A file can embed hundreds of megapixels, so nothing holds every pattern decoded at once. Ids found nowhere keep painting with the seeded grain and are named in one import warning. These are the user's own file contents, imported like a .pat; nothing is bundled.
- **Unmapped settings**: `collect_unmapped_settings` records preset keys in use that Patchy cannot honor and `import_abr` turns them into ONE warning line. Named features get translated labels (Brush Projection, Brush Pose, Tilt Scale with a Pen Tilt size control, Wetness and Mix jitter, Protect Texture, Dual Brush mode or scattering/flip, Spacing turned off); anything else is listed by its raw key when its value is set (true, non-zero, non-empty), so a future Photoshop key never vanishes silently. `Intr` false (spacing off) means Photoshop stamps per input event; Patchy keeps its spatial cadence (brushes.md, Flow and Airbrush) and uses the stored `Spcn`. `TxtC` (Texture Each Tip) is accepted silently: Patchy textures each dab, with static depth either way.

## Descriptor mapping

`parse_brush_dynamics` (abr_reader.cpp) imports the supported dynamics: Shape/Scatter/Transfer fields, texture `useTexture`/`textureScale`/`textureDepth`/`InvT`/`Txtr` plus `textureBlendMode` (4-char codes like `CBrn`/`Hght` or long ids like `linearHeight`), `textureBrightness`, `textureContrast`, `Nose` (Noise), the static tip flips `Brsh.flipX`/`flipY`, one `dualBrush.Brsh` secondary tip's diameter/hardness/spacing, Color Dynamics `useColorDynamics`/`clVr`/`H   `/`Strt`/`Brgh`/`purity`/`colorDynamicsPerTip`, and `Wtdg` (Wet Edges). Without a resolvable pattern the identity is hashed into a stable seed and the name selects the closest generated grain family. Input-driven `textureDepthDynamics` is deliberately reduced to the static `textureDepth`, with a per-brush import notice. Base `Angl`/`Rndn` come from the primary `Brsh` tip object. Options-bar Flow imports from `toolOptions.flow`, Airbrush from preset `Rpt ` (live key `repeat`); both apply only when `toolOptions.brushPreset` is true and the tip is picked; a library change never resets the working brush. `bVTy` mapping: 0 Off, 1 Fade, 2 Pen Pressure, 3 Pen Tilt, 4 Stylus Wheel, 5 Rotation, 6 Initial Direction, 7 Direction. Every supported dynamic's control + `fStp` imports; on non-angle dynamics bVTy 0 maps to the slot default (GlobalDefault for size/roundness/opacity, Off for flow/scatter/count/color), and the angle-only 6/7 degrade to Off (`non_angle_control_from_bvty`).

## Fixtures

`test-fixtures/abr/myer-settlement-brushes.abr` (CC0, see NOTICE.txt; 148 brushes, v6.2, dynamics all disabled, pins the defaults path) and the self-authored `photoshop-dynamics.abr` / `photoshop-dual-brush.abr` (exported from Photoshop 2026, one probe brush each; the dual fixture pins imported secondary diameter/hardness/spacing without a warning). The dynamics fixture's non-angle `bVTy` values are all 0 (angle = 7 Direction), so it pins the bVTy-0-to-GlobalDefault/Off mapping plus included Flow 100/Airbrush off. The synthesized v6 file in `abr_v6_desc_controls_import` (the test writes the desc TLVs itself) pins explicit control imports and the texture/color/wet fields. Bigger CC0 sets for manual tests live in `local-test-fixtures/abr-sets/`. `abr_v6_computed_tips_hierarchy_patterns_and_unmapped_settings` and `abr_v1_computed_brush_imports_as_rendered_tip` synthesize their files in-test (descriptors through `write_descriptor`, patterns through `serialize_patterns_block`); `ui_abr_import_fills_folders_patterns_and_size` imports one through MainWindow's libraries.
