# Bitmap brush tips, dynamics and effects, Flow/Airbrush, Mixer Brush, Pattern Stamp, and .abr import

The scripting API's `layer.drawStrokes` drives native Brush/Eraser/Mixer paths,
tips, dynamics and timed inputs without input events. Explicit temporary settings
restore the artist's controls. `patchy.brushes` provides resource discovery,
swatches, creation/import, and complete saved presets. See
[brush-automation.md](brush-automation.md) and the packaged `patchy.d.ts`.

Deep reference for the brush-tip stamping engine, tip library/UI, brush dynamics, and .abr import. Repository-wide determinism and append-only identifier rules (e.g. `BrushDynamicControl`) remain in `AGENTS.md`; shared UI conventions live in [ui-conventions.md](ui-conventions.md), and the binding patent summary is in [legal-constraints.md](legal-constraints.md).

Brush, Pattern Stamp, and Eraser can stamp bitmap **brush tips** in addition to the procedural brushes. Two procedural footprints exist, `core BrushShape` Round and Square, selected in the tip picker as the reserved ids `builtin.round` and `builtin.square` (script identifiers; never change them). The Square (September 2026) is procedural on purpose: a hard, unrotated square snaps to the pixel grid, so a dab at any sub-pixel position covers exactly (2 x radius + 1)^2 whole pixels and a size-1 square is the one pixel under the pointer, with no partial-alpha fringe (a scaled bitmap square could not do that). Rotation, roundness (a rectangle) and Soft use the geometric footprint with a Chebyshev feather that keeps the corners square (`square_brush_coverage` in `src/core/pixel_tools.cpp`); square strokes take the elliptical brushes' dab-spacing path. Square applies to the Brush and Eraser (`apply_brush_tip_to_options` sets `EditOptions::brush_shape`); Pattern Stamp, Clone, Mixer and the retouch brushes stay round. With session dynamics active the Square stamps through a synthesized solid 256 px square the way Round stamps through its disc. The cursor and the large-brush overlay draw a square outline rotated by the base angle. `tool_square_brush_dabs_are_pixel_snapped_and_solid` (core) pins the footprint math.

## Core stamping engine

- Core stamping: `src/core/brush_tip.hpp/.cpp` (`BrushTip` = 8-bit grayscale coverage mask + default spacing; `BrushTipMipChain` box-filtered halvings built once per tip; `ScaledBrushTip` resampled per brush size) and `src/core/pixel_tools.cpp` (`paint_tip_dab`, `paint_tip_segment`). `EditOptions::brush_tip` (non-owning `const ScaledBrushTip*`, null = procedural) plus `brush_tip_spacing` select the stamp path. Rotation/roundness/subpixel apply per-dab in the inverse map, so the scaled cache depends only on size (pressure size quantizes to 2px steps while a tip is active; an 8-entry LRU caches scaled stamps). The stateful `paint_brush_segment(..., BrushTipStrokeState&)` overload carries dab spacing across the stroke smoother's short segments; state resets in `CanvasWidget::clear_brush_stroke_tracking()`.
- **Soft** applies to bitmap tips as an outward edge feather: `patchy::soften_scaled_brush_tip` (3x separable box blur; pads the stamp and shifts the anchor), via `CanvasWidget::scaled_brush_tip_for(size, softness)` cached by (size, feather). Feather = size x softness% / 400. A soft tip's center coverage can drop below 100% for thin tips, so soft erase leaving residue is correct.
- All brush/eraser strokes (procedural and bitmap-tip) share the per-stroke snapshot compositor (`install_brush_stroke_compositor` + `write_brush_stroke_pixel_from_snapshot`): overlapping dabs accumulate alpha toward the stroke's opacity cap and re-blend against a stroke-start snapshot, so soft overlaps (self-crossings, edge-to-edge stamps like brick) never seam. Flow scales each dab before that accumulation; the default 100% Flow path stays byte-identical. Tips route through it via `EditOptions::stroke_pixel_writer`, honored in `paint_tip_dab` (`ui_brush_tip_soft_stamps_accumulate_without_seams` pins this). The layer-mask brush uses the older max-coverage cap at 100% Flow and the accumulation equation for reduced Flow or Airbrush buildup. Clone and local adjustment brushes keep the max-coverage cap (`capped_stroke_coverage`).
- Brush size maxes at **1024** via `kMaxBrushSize` everywhere (canvas, Alt+drag, options bar); Quick Select has its own 512px cap.
- `[`/`]`, Shift+`[`/`]`, and the pen-button size actions resize **proportionally**: `proportional_brush_step` (main_window.cpp) grows 10% (Shift 30%) with a 1-px floor (2 px Shift); grow = `(1+f)`, shrink = `1/(1+f)`, so `]` then `[` round-trips. Do not revert to a fixed step (large brushes crawl). `ui_photoshop_shortcuts_are_registered` pins the steps (20->22/26, 100->110/130, 5->6); retune factors and test together.

## User library and built-in default tips

- The user library is `src/ui/brush_tip_library.*`: `<settings dir>/brushes/` (`%APPDATA%/Patchy/brushes/`) with one grayscale PNG (coverage mask) + one JSON sidecar (`{"name", "spacing", "folder"}`) per tip; ids are the UUID filename stems. Corrupt files skip that tip only. Tests pass a temp dir to the constructor. Tips carry an organizational **folder** (empty = ungrouped, sorted first); `import_abr` files everything into a folder named after the .abr ("File / Group" for the file's own folders); `remove_tips()` bulk-deletes with one `changed()`.
- **Built-in default tips** (`src/ui/default_brush_tips.*`): 40 parametric tips (16 natural-media, 20 v3 stamps, 4 v4 effect examples: Textured Chalk, Dual Brush Dots, Color Scatter, Wet Edge Wash), all deterministic seeded noise/SDF math, no binary assets. Seeding into the "Patchy Defaults" folder is gated by the `brushes/defaultTipsVersion` int; each spec carries `since_version` and startup calls `restore_default_tips(stored_version)`, so a version bump seeds only newer tips and deleted older defaults stay deleted. Direction-control stamps author their art with bitmap +X = direction of travel. Tiling stamps (brick road, cobblestone, rope) are square/X-periodic with coverage touching the tile edges, because `add_tip` crops to content and dab advance = brush size x spacing (spacing 1.0 = exact butt joint). UI tests suppress seeding via `clear_brush_tip_test_state()`; `ui_default_brush_tips_seed_once_and_render_sheet` renders every tip (artifact `ui_default_brush_tips_sheet.png`).
- Deleted defaults are recoverable: the parameterless `restore_default_tips()` re-adds missing ones, matched by name within the defaults folder. The manager's "Restore Default Brushes" button pairs it with `reset_default_tips_to_factory()`, which snaps customized default-folder tips (spacing/tip shape/dynamics) back to the shipped spec and rewrites a mask PNG in place (same id) when its pixels differ from the current generator output, healing pre-fix artwork. Only the button does this; version-gated startup seeding never resets customizations or masks.

## Picker, manager, cursors

- The options-bar preset combo (`brushPresetCombo`) lists `builtin_brush_presets()` (Round, Square, Soft Round, Hard Round, Pencil, Ink, Airbrush; `src/ui/brush_presets.*`) ahead of the saved automation presets. Every built-in preset selects its procedural tip: `BrushPreset::tip_id` is `builtin.square` for Square and empty (Round) for the rest, so picking any preset while a bitmap tip is active returns to a procedural tip, with no dynamics. The bitmap "Square" in the Patchy Defaults folder is unrelated and stays (it is a sampled tip with soft scaled edges). Scripting: `brushes.getPreset("square")` reports `tipId: "builtin.square"`, `listTips()` lists both procedural tips first. `ui_square_brush_preset_paints_square_tip_and_round_presets_restore_round` pins all of it.
- `BrushTipPicker` (options-bar popup; Brush, Pattern Stamp, Eraser) and `request_brush_tip_manager` (`src/ui/brush_tip_manager_dialog.*`): QTreeWidget with expandable folder rows, Extended multi-selection, bulk delete (button or Del; a folder row means all its tips), folder line-edit for the selection, live engine-rendered stroke preview. "Define Brush Tip from Selection" (Edit menu, hotkey id `edit.define_brush_tip`) captures inverted luminance x alpha x selection coverage (dark pixels paint, Photoshop semantics). The working brush is application-wide (see Current brush) and remembered between launches with its base under `tools/workingBrush` (JSON in the script vocabulary); without one, or when its tip no longer exists, a launch starts from the "Round" startup preset (round tip, size 25, 100% opacity, 0% soft; `default_startup_brush_preset_id` in `load_tool_settings`). `ui_working_brush_survives_restart` pins both. Eraser opacity/softness reset; only `tools/eraserSize` survives a restart, and the legacy `tools/brush*`/`eraser*` per-setting keys are dead.
- Dialog spin boxes keeping their - / + buttons must append `dialog_spinbox_button_style()` (src/ui/dialog_utils) to the dialog stylesheet AFTER all children exist (see that header's gotcha note).
- Every Size/Soft footprint tool (`tool_uses_brush_footprint_cursor` in canvas_widget_shared: Brush, Mixer, Pattern Stamp, Eraser, Clone, Healing, Spot Healing, Smudge, Dodge, Burn, Sponge, Blur, Sharpen, plus Quick Select via its own path) drops the pixmap cursor past the ~155px display cap and becomes a crosshair plus a canvas-overlay outline (`brush_outline_uses_overlay`/`draw_brush_hover_outline`). This also keeps large outlines working on wasm, where browsers reject oversized bitmap cursors. Only tip-stamping tools (`tool_paints_with_brush_tip`: Brush, Mixer, Pattern Stamp, Eraser) trace the active tip's outline (`CanvasWidget::apply_brush_tip_cursor`); the retouch/toning tools always show the procedural circle, matching their procedural strokes. Base shape only (no per-dab rotation/tilt). On stationary `[`/`]` resizes, `invalidate_brush_hover_outline(previous)` must erase old union new: `update_tool_cursor()` repaints only the new rect, so shrinking would strand the old rings. A `grab()` test repaints the whole widget and cannot catch this; manual-verify.
- Holding **Alt** over a paint/shape/fill tool (`tool_uses_alt_left_for_color_pick`) turns left-click into a colour pick; `update_tool_cursor` shows the eyedropper cursor, hotspot on the lower-left tip, checked before the brush/overlay branches. The `eventFilter` swaps the cursor the instant Alt toggles, driven by the event's folded modifiers via the transient `alt_color_pick_cursor_override_`, never `QApplication::keyboardModifiers()` (it lags and leaves the eyedropper stuck; Zoom/selection badges fold modifiers for the same reason). The glyph is one shared cached helper, `patchy::ui::eyedropper_cursor()` (ui/tool_cursors), also used by the Eyedropper tool and the colour picker's "Pick Screen Color" overlay so they never drift.
- The tip picker popup resizes via an embedded QSizeGrip (frameless Qt::Popup has no native resize border); size persists as `ui/brushTipPickerPopupSize`, saved in closeEvent (outside-click dismissal goes through close()). The grip is custom-painted (`VisibleSizeGrip`; the native one is nearly invisible on themed chrome).

## Current brush

`ui/current_brush` (`CurrentBrush`, owned by MainWindow) is the one owner of the working brush: tip (procedural id, library id, or a saved preset's snapshot), Size/Opacity/Flow/Soft/Airbrush (the paint group the other footprint tools share), base angle/roundness, spacing override, and dynamics, plus the base it was picked from (preset or tip) and `modified()`. Writers go through `edit()`/`pick()`/`pick_tip()`; `MainWindow::push_current_brush_to_canvas` is the only path to a canvas, and canvas gestures (Alt-drag, number keys) fold back through `fold_canvas_brush_values`. The Eraser keeps its own size group but stamps the working tip. A preset pick replaces the whole brush. A tip pick keeps Size (unless an imported tip carries `defaultSize`)/Opacity/Soft and loads the tip's sidecar shape and dynamics; Round and Square share the session's last procedural shape and dynamics. Edits never write a sidecar or a saved preset. A spacing override (Photoshop's Spacing, a fraction of the diameter; unset keeps each tip's own) also drives Round and Square: their strokes take the dab path at that cadence, Square stays square there (`current_brush_edit_options` sets the footprint for Brush and Eraser), and no off-cadence dab lands beside the press or at release (`ui_working_brush_spacing_drives_procedural_dabs`). Unset spacing keeps the historical capsule and soft-dab output. `ui_current_brush_tracks_base_and_reaches_canvas` pins it. Brush Settings locks (`CurrentBrush::locks`, `picked_over`) keep locked sections through a pick; the Brushes and Brush Settings panels are in [brush-panels.md](brush-panels.md).

## Brush dynamics (Photoshop-compatible)

Modeled: per-dab Shape Dynamics (size/angle/roundness jitter with minimum floors, flip X/Y jitter), Scattering (scatter %, both axes, count 1-16, count jitter), Transfer (opacity and Flow jitter with independent minimums), static Tip Shape (base angle/roundness), Brush Texture (a generated Fine Grain/Canvas/Speckle grain or a Pattern library tile, with scale/depth/invert, Brightness/Contrast, and Photoshop's ten texture Modes; see [brush-texture.md](brush-texture.md)), Dual Brush (multiplies the primary tip by one repeated computed round mask with size/hardness/spacing), Color Dynamics (foreground/background interpolation plus hue/saturation/brightness jitter and purity, per dab or per stroke), Wet Edges, and Noise. Noise pulls each dab's soft (partial) coverage 75% of the way toward hard 0/1 against a static splitmix64 hash of the document pixel (`apply_brush_noise`): grain that stays put on the canvas, draws no randomness (the RNG contract is untouched), never samples the canvas, and ignores every stroke input, so it sits inside the same static-mask boundary as Brush Texture. Wet Edges builds one max-coverage union mask for the whole stroke, lightens the wash interior, and concentrates paint in its low-coverage boundary; individual dab boundaries inside the stroke are never wet edges. This is observed Photoshop behavior: watercolor edge pooling, not canvas smearing (the tooltip points to Smudge for that).

**Every input-driven dynamic carries a Photoshop-style Control** (Off / Fade with per-dynamic fade steps / Pen Pressure / Pen Tilt / Pen Rotation / Stylus Wheel = tablet tangential pressure; angle adds Initial Direction / Direction). Size/roundness/opacity controls are tri-state against the global pen prefs: the default `GlobalDefault` leaves `input/pen/*` authoritative (pre-dab scaling in `effective_brush_input`); any other value (including Off) makes the brush own that aspect and suppresses the matching global modulation (size<->pressureSize, opacity<->pressureOpacity, roundness<->tiltShape's tilt->roundness), gated by `brush_dynamics_authoritative` (Brush tool only, never the eraser end/tool, Clone/Smudge, or mask painting). Flow has no matching global pen preference, so its default control is Off. Off means the brush ignores the pen for that aspect, with no per-dab work: `active()` treats Off/GlobalDefault as inactive, so an Off-only Round brush stays on the procedural capsule path (the options-bar badge keys on `brush_dynamics_is_default`, not `active()`). Controls map the input c in 0..1 into [minimum, 1] (count fades toward 1, scatter scales by c, angle maps c to 0..360 deg); a missing pen input reads as 1.0 so a mouse paints at full value. Controls never consume RNG draws; the draw-order contract gates stay keyed on static config (`tool_brush_tip_controls_at_full_value_change_nothing` pins this). Only append to `BrushDynamicControl`: combo indices and casts depend on the existing order.

- Core engine `src/core/brush_dynamics.hpp/.cpp`: `BrushDynamics` carried by value in `EditOptions`; default-constructed = `active()==false` = the historical stamp path bit-for-bit, zero RNG draws. Per-dab variation rides the inverse map (`TipDabTransform`: inverse_scale + flip signs); size jitter only SHRINKS (Photoshop semantics), so the scaled-tip LRU and 2px pressure quantization are untouched. The RNG is splitmix64 with explicit uniform mapping, NEVER std::uniform_*_distribution (implementation-defined output breaks cross-toolchain pixel tests). The draw-order contract lives in brush_dynamics.hpp; tests depend on it. Stroke state (RNG, fade step index, smoothed + initial direction) lives in `BrushTipStrokeState`, seeded from `EditOptions::brush_dynamics.seed` on the first dab; CanvasWidget seeds per stroke in `clear_brush_stroke_tracking()` (`set_brush_dynamics_test_seed` is the UI-test hook).
- Dynamics are Brush-tool only: erase strokes strip `brush_dynamics` in draw_brush_segment / draw_brush_at. The procedural **Round brush supports dynamics too**: its capsule renderer has no dab loop, so while `brush_dynamics_.active()` a Round stroke stamps through a synthesized 256px disc tip (`round_dynamics_tip_mips()`, spacing 25%; Soft feathers it like any bitmap tip; pressure sizes quantize to 2px). Inactive dynamics keep the capsule path bit-for-bit; a Round ERASE stroke always stays procedural. `draw_brush_at` routes tip presses through a stateful zero-length `paint_brush_segment` so the press dab is not re-stamped by the first move segment (else it visibly double-jitters).
- Per-tip persistence: `BrushTipEntry` carries dynamics + base angle/roundness; the JSON sidecar has top-level `"baseAngle"`/`"baseRoundness"` and a `"dynamics"` object (camelCase fractions 0..1, scatter 0..10, string enum tokens like `"direction"`), written only when non-default. Texture persists `textureEnabled`/`textureStyle`/`textureScale`/`textureDepth`/`textureInvert`/`textureSeed`/`textureMode`/`textureBrightness`/`textureContrast`/`texturePatternId`/`texturePatternName`; Dual Brush its enabled/size/hardness/spacing fields; Color Dynamics its enabled/jitter/control/fade/purity/per-tip fields; Wet Edges as `wetEdges`; Noise as `noise`; the static Brush Tip Shape flips as `tipFlipX`/`tipFlipY` (they ride `EditOptions::brush_flip_x/y`, so erase and Pattern Stamp strokes mirror too, combine with the flip jitters by XOR, and never activate the dynamic path or draw randomness). Control tokens: `"global"`/`"off"`/`"fade"`/`"penPressure"`/`"penTilt"`/`"penRotation"`/`"stylusWheel"`. Missing/unknown keys read as defaults (no sidecar migration). Imported ABR tool settings persist as optional top-level `toolFlow`/`toolAirbrush`, a captured preset size as `defaultSize`. Adding a dynamics field means updating BOTH `brush_dynamics_is_default` and `persisted_dynamics_equal`; missing one silently breaks sidecar writes or factory reset.
- The Brush Settings panel (the options-bar **Dynamics** button shows it; [brush-panels.md](brush-panels.md)) edits the working brush, never the tip's sidecar; the manager's "Edit Dynamics..." edits a tip's stored defaults, which load on the next pick of that tip. The hidden `textureSeed` is retained while the form edits visible texture settings. The manager's stroke preview renders dynamics with a fixed seed.
- ABR import maps Photoshop presets onto these settings; the descriptor key mapping, `bVTy` controls, and patent reductions live in [abr-import.md](abr-import.md).
- With `input/pen/tiltShape` on and the tip's angle control PenTilt/PenRotation, the per-dab path owns the angle and effective_brush_input skips its tilt-angle assignment (tilt->roundness still applies unless the roundness control overrides it), avoiding double rotation. Known divergence (pre-existing for jitter): dab spacing tracks the base brush size, not the per-dab controlled size.
- The built-in default tips ship with **curated dynamics** (`DefaultBrushTipSpec::dynamics`); Canvas, Square, Calligraphy, Dotted Line, and RTsoft Logo deliberately stay plain. `brushes/defaultTipsVersion` = **4** (v3 added the 20 stamps, v4 the four effect presets). Upgrades from < 2 also run `BrushTipLibrary::apply_default_tip_dynamics()` once. It must never re-run for stored version >= 2: it cannot distinguish a deliberate post-v2 reset from "never migrated" and would stomp it. It only touches default-folder tips still at untouched defaults; user customizations always win. "Restore Default Brushes" re-adds missing tips with curated dynamics but never re-migrates existing ones.
- The dynamics form is the shared `BrushDynamicsPanel` (brush_dynamics_popup.*), one page per Brush Settings section: the Brush Settings panel places the pages; the manager's "Edit Dynamics..." button (single selection) shows them all in a child dialog with live debounced apply + preview refresh. Control combos map items via `addItem(text, int(enum))`/`currentData`, so display order is decoupled from enum values, EXCEPT the pre-existing angle combo, whose item indices equal the enum values (a UI test sets index 6 = Direction; append-only). Tips with dynamics or a non-default tip shape get a blue corner badge (`brush_tip_thumbnail_with_badge`) and a " - dynamics" tooltip suffix.
- Patent boundaries (reviewed July 15, 2026): Shape Dynamics and Scattering remain clear. The binding design boundaries for Brush Texture (US 10902645, US 8896579), Color Dynamics (US 10924633), Wet Edges, and Dual Brush live in [legal-constraints.md](legal-constraints.md); keep the implementation comments in sync with that file. Wet Edges' curve was calibrated from observed Photoshop 2026 output using a scripted hard Round stroke (no Adobe code or artwork involved) and sits outside the now-expired US 6198489.
- PSD/PSB compatibility is raster-exact: brush configuration is application/library state; documents store only painted pixels, which other editors reopen identically. ABR import is the compatibility path for brush settings.

## Deliberate limitations

Layer-**mask** painting and Clone/Healing/Smudge/Dodge/Burn/Sponge/Blur/Sharpen stay procedural. The four effect families apply to Brush strokes only. Dual Brush imports one secondary tip's basic geometry, not its own scatter/dynamics stack or arbitrary blend mode. Brush Texture has no Texture Each Tip toggle or depth dynamics (static by design); a brush without a resolvable pattern uses a generated grain.

## Pattern Stamp

Pattern Stamp paints the selected Pattern Library tile through the common brush footprint. The options bar exposes Pattern, Manage, Aligned, Size, Opacity, Flow, Soft, and Tip; numeric fields use the shared chevron popup slider, not permanent sliders. Manage opens the existing Pattern Manager, so generated defaults, image imports, and imported `.pat` entries work without a second store. The pattern id and Aligned state persist as tool settings; pattern pixels stay in the library.

Aligned anchors the tile grid on the first stroke and keeps that document-space origin across later strokes; unaligned, every stroke centers the tile under the initial pointer. Shift-click stroke connection, number-key Opacity, Shift+number-key Flow, selection coverage, transparent-pixel locking, palette snapping, layer expansion, undo, and bitmap tips reuse the existing brush paths. Brush dynamics are deliberately disabled for Pattern Stamp: a selected bitmap tip is a static mask, and Round stays procedural.

The implementation is a direct modulo lookup into one immutable RGBA tile; the binding boundary (no destination inspection, no content-derived or input-driven texture assembly; US 9864922, US 10902645) lives in [legal-constraints.md](legal-constraints.md). Keep the constraint comment in `CanvasWidget::install_brush_stroke_compositor` in sync with that file.

Pattern Stamp is destructive raster painting matching Adobe's documented basic behavior; PSD/PSB contains only ordinary layer pixels (no private metadata, no live pattern dependency). `ui_pattern_stamp_alignment_palette_and_psd_round_trip` pins both alignment modes, palette snapping, and exact layered PSD reopen.

## Flow and Airbrush

The Brush options bar has separate Opacity and Flow plus an Airbrush toggle. Opacity is the maximum paint applied during one stroke; Flow is the fraction metered by each spatial dab; Transfer Flow dynamics multiply that per-dab fraction before the Opacity-capped accumulator. Reduced-Flow Round strokes use the fixed dab-spacing path even with a hard edge, so output depends on document distance, not mouse-move event density. The default 100% Flow, Airbrush-off path retains the historical renderer bit for bit. Shift+number keys set Flow; while Airbrush is on the assignment flips, Photoshop-style (bare numbers set Flow, Shift+numbers set Opacity).

Airbrush adds one copy of the current flat 2D stamp every 50 ms while the pointer is held, including stationary. Timer stamps advance Shape and Transfer dynamics (including Fade) but deliberately suppress Scattering and Count; pointer movement retains full dynamics. Grayscale mask painting keeps the no-dynamics limitation above. The same Flow accumulator and Opacity ceiling apply to movement and timer dabs on both pixel and mask targets. The timer stops on release, focus loss, tool change, document-target change, or Airbrush off. The built-in Airbrush preset: plain fully soft 56 px Round tip, Round dynamics session reset, 100% Opacity, 12% Flow, timed buildup on. Do not add airbrush-only duplicate defaults; Smoke, Spray, Spatter, and Stipple cover those shapes. Flow and Airbrush belong to the working brush and the Eraser's group like Size/Opacity/Softness.

Patent review (July 15, 2026): this is the classic flat-stamp behavior Adobe documents: Flow accumulates only to Opacity and a held stationary airbrush builds color. The binding boundary (no particles, 3D spray cone, stylus-pose projection, velocity-dependent deposition, bristle or fluid simulation, wet/dirty paint, or bidirectional transfer; US 8854342, US 9600907, US 10489937) lives in [legal-constraints.md](legal-constraints.md). Keep the matching constraint comment in `CanvasWidget::timerEvent` in sync with that file.

`ui_brush_flow_builds_only_to_opacity_cap_and_round_trips_psd` pins the Opacity ceiling and exact layered PSD reopen; `ui_airbrush_fast_strokes_ignore_mouse_event_density` pins the spatial cadence.

## Local adjustment brushes

Dodge, Burn, Sponge, Blur, and Sharpen share one stroke-start snapshot engine in `canvas_widget_brush.cpp`. They use the procedural Size/Soft footprint plus a separate Strength cap. Dodge and Burn offer Shadows/Midtones/Highlights and Protect Tones; Sponge offers Saturate/Desaturate and Vibrance. Settings are application-wide and persist under stable `tools/local*` and `tools/sponge*` keys. The Detail flyout holds Smudge/Blur/Sharpen; the Toning flyout holds Dodge/Burn/Sponge.

The algorithms are fixed and user-directed. Blur is one alpha-aware 3x3 Gaussian convolution; Sharpen subtracts that fixed blur once from the center sample; Dodge and Burn apply a fixed luminance-range weight through channel screen/multiply or a tone-protecting equal channel offset; Sponge scales chroma around fixed Rec. 709 luma, optionally reducing the effect for already-saturated colors. Nothing ranks pixels, detects edges or regions, samples stroke-start color statistics, searches patches, deconvolves, or changes the footprint based on image content. Keep the patent-boundary comment at the implementation site in sync with `docs/patent-research.md`.

These tools preserve the active layer's alpha and never expand its bounds; selections and palette-mode snapping apply before the write. Results are ordinary destructive RGBA layer pixels; layered PSD/PSB round-trips are exact. `ui_local_adjustment_brushes_use_fixed_math_and_round_trip_psd` pins the five algorithms and every output byte after a PSD read/write cycle.
